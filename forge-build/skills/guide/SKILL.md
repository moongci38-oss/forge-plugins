# guide — 가이드 한 양식

> 설명 원문(#3691 목록 예산으로 줄이며 여기로 옮김): 시스템 사용 가이드·설치 안내를 한 양식으로 쓰거나 같은 주제의 기존 가이드를 고치고 검사기로 확인해 저장한다(주제당 한 파일). 사용자가 '가이드 써줘'·'사용 가이드'·'사용법 정리해줘'·'설치 안내'·'팀원 안내문'·'런북'·'매뉴얼'·'how-to'·'팀원 온보딩 문서'를 요청하거나, 기능을 머지·배포한 뒤 사람이 따라 할 순서를 문서로 남길 때 쓴다. SKIP: 작업계획서는 /work-plan · Spec 문서는 /forge-spec · 묶음 허브·테스트 요청은 /forge-bundle · 새 레포를 forge 에 올리기는 /onboard · 레포 안 개발 문서(README·ARCHITECTURE·코드 주석)는 해당 아님.

**역할**: 사람이 따라 할 시스템 사용법·설치·배포 순서를 **한 양식**으로 쓴다. 쉬운 말 · 결론 먼저 · 전 PC 동일 한 장.
**컨텍스트**: 사람이 가이드·안내문·런북을 요청하거나, 기능이 머지·배포돼 팀원이 따라 할 순서가 생겼을 때. 가이드만 쓴다 — 코드·설정은 고치지 않는다.
**출력**: 가이드 폴더의 `<topic>.md`(정본 — 새로 만들거나 기존 파일을 고친다) + 같은 이름 `<topic>.html`(검사기 `--html` 이 만든다 · 사람은 이 HTML 을 브라우저로 본다) + 검사기 `OK` 줄.

## 절차

1. **폴더 정하기** — 손으로 정하지 않는다:
   ```bash
   L="${FORGE_ROOT:-$HOME/forge}/shared/scripts/guide-lint.py"
   DIR=$(python3 "$L" --guide-dir)
   ```
   순서: 환경변수 `FORGE_READONLY_GUIDE_DIR` → `<프로젝트 루트>/.claude/readonly-session.json` 의 `guide_dir` → 기본은 세션으로 갈린다(판정은 검사기 한 곳): 쓰기 세션 = forge 레포 `${FORGE_ROOT:-$HOME/forge}/docs/guides`(머지되면 팀원 PC 가 `forge-update` 로 받는다 · 검사기가 stderr 에 PR 안내 1줄) · 읽기 세션이거나 forge 레포를 못 쓰면 `${FORGE_OUTPUTS:-$HOME/forge-outputs}/docs/guides`(세션 종료 때 autosync 가 커밋·공유). 개인·산출물 가이드는 설정 키 `guide_dir`(예: `"${FORGE_OUTPUTS:-$HOME/forge-outputs}/docs/guides"`)로 forge-outputs 에 둔다. 읽기 전용 세션이 쓰기를 허용하는 폴더와 같다.
2. **같은 주제 찾기(주제당 한 파일)** — `ls "$DIR"` 와 `grep -ril "<주제 낱말>" "$DIR" --include=*.md` 로 같은 주제 파일을 찾는다. 있으면 **그 파일을 고친다**(이름 유지 · 머리말 `updated:` 를 오늘로) — 새 날짜 파일을 만들지 않는다. 없으면 새 파일 `<topic>.md`(날짜 없는 이름 · topic = 영문 소문자-하이픈 슬러그).
3. **실측** — 가이드에 적을 명령을 실제로 돌려 본다. `## 되면 보이는 것` 에는 실제 출력을 적는다. 돌릴 수 없으면 그 줄에 "확인 필요"(추측으로 채우지 않는다).
4. **쓰기** — 틀은 `assets/guide-template.md`(쓸 때 Read). 절 순서·이름을 바꾸지 않는다: 쉽게 말하면 → 누가·언제 → 준비 → 순서 → 되면 보이는 것 → 막히면 → 확인 명령.
   - 쉬운 말 · 결론 먼저 · 짧은 문장 · 전문용어는 풀어쓴다(수치·명령은 그대로).
   - 설치·배포(`kind: install|deploy`)면 `## 순서` 에서 `git fetch` → `git checkout <브랜치>` → `git pull` 을 설치 명령 **앞에** 둔다.
   - PC·운영체제마다 절을 갈라 쓰지 않는다 — 차이는 스크립트가 판정하게 하고 명령 1개를 적는다.
   - 해당 없는 칸은 `해당 없음 — <사유>` 1줄. 빈 절은 안 된다.
5. **HTML 만들기 → 검사** — `python3 "$L" --html "$DIR/<topic>.md"` 로 같은 이름 `<topic>.html` 을 만든 뒤 `python3 "$L" "$DIR/<topic>.md"`. rc 1 이면 지적 줄을 모두 고치고(md 를 고쳤으면 `--html` 부터 다시) rc 0 까지 돌린다.
   - HTML 은 손으로 고치지 않는다 — 정본은 md 하나다. 검사기가 HTML 짝이 없거나 md 와 다르면 지적한다.
6. **올리기(DIR 이 forge 레포 안일 때만)** — 공유 체크아웃에 미커밋으로 두지 않는다(팀원에게 안 간다). 1번 직후에 `git -C "${FORGE_ROOT:-$HOME/forge}" worktree add -b docs/guide-<topic> "${FORGE_ROOT:-$HOME/forge}/.claude/worktrees/guide-<topic>" origin/develop` 로 가지를 만들고 DIR 을 그 워크트리의 `docs/guides` 로 바꿔 2~5번을 한다. 끝나면 `.md`·`.html` 두 파일만 `git add` → 커밋 → `/forge-pr` 로 develop 에 PR. 읽기 세션은 커밋할 수 없으므로 DIR 이 forge-outputs 로 나온다(이 단계 없음).
7. **보고** — 파일 경로 2개(`.md` 새로 만듦/고침 · 사람이 열 `.html`) · 검사기 `OK` 줄 · PR 번호(6번을 했으면) · 사람이 직접 해 볼 것 1줄.

## 하지 않는 것
- 프로젝트·조직·PC 이름이나 절대 경로를 이 스킬·양식에 박지 않는다 — 저장 위치는 설정 데이터로만 바꾼다.
- 기존 가이드 여러 장을 이 김에 합치거나 옮기지 않는다 — 요청받은 주제 1개만.

## 실패 시 출력
- 검사기 rc 1 → 지적 줄(`<파일>:<줄>: <지적>`)을 그대로 보이고 고친 뒤 재실행. 3번 넘게 같은 지적이면 그 줄과 함께 "미완료"로 보고한다.
- 검사기 rc 2 → 사용법·파일 경로 오류 1줄을 보이고 멈춘다.
- 같은 주제 파일이 이미 여러 개(옛 판 중복)면 가장 최근 파일을 고친다. 그때 남는 지적이 `같은 주제 파일이 이미 있다` 뿐이면 그 줄과 함께 "중복 — 정리 필요"로 보고한다(다른 파일은 지우지 않는다).
