# prd-review — PRD 5관점 검토

> 설명 원문(#3691 목록 예산으로 줄이며 여기로 옮김): PRD 1개를 사업·디자인/UX·개발·QA·보안 5관점으로 동시에 검토해 지적마다 등급(심각/주의/제안)과 해결안 1줄을 남긴다. /prd 6단계가 부르고, 사용자가 'PRD 검토'·'PRD 리뷰'·'기획서 관점별 검토'를 요청할 때 쓴다. SKIP: Spec·계획서 2차 리뷰는 /forge-review --stage plan.

**역할**: PRD 하나를 다섯 관점이 동시에 읽고, 예외·권한·측정 빈틈을 기획 단계에서 찾아 고칠 거리로 바꾼다.
**컨텍스트**: `/prd` 6단계(초안 직후 1회) 또는 사람이 PRD 경로를 주며 검토를 요청할 때.
**출력**: PRD 옆 `<PRD 이름>-review.md` 1개 + PRD 제목 바로 아래 요약 3줄 + 검사기 `OK` 줄.

## 관점 (다섯 개 고정 — 절 이름 그대로 쓴다)

| 절 | 보는 것 |
|---|---|
| 사업 | 타깃·문제·성공 지표(목표치·측정법)·범위·수익 가정 |
| 디자인/UX | 핵심 흐름이 끊기는 곳·빈 상태·오류 화면·접근성·화면 목록과 흐름의 어긋남 |
| 개발 | 만들 수 있는가·데이터 모델·외부 연동·성능 한계·모호한 요구 |
| QA | 수용 기준이 확인 가능한 문장인가·경계값·실패 경로·테스트 시나리오 빈칸 |
| 보안 | 인증·권한(역할별 접근)·개인정보·결제·입력 검증·감사 기록 · 재화·확률·가격·권한 같은 핵심 로직은 서버에 두는가(화면 쪽은 복제·조작된다는 전제) |

**등급** — 심각 = 이대로 만들면 사용자·데이터·돈에 실제 피해가 나거나 만들 수 없다 · 주의 = 만들 수는 있지만 재작업이 생긴다 · 제안 = 더 좋아진다.

## 절차

1. **PRD 를 읽는다** — 경로 1개. 없거나 읽을 수 없으면 [STOP].
2. **다섯 관점을 동시에 돌린다** — Agent 도구로 **서브에이전트 5개를 한 메시지에** 띄운다(`model: "sonnet"` · 읽기 전용 · 관점마다 1개). 브리프에는 PRD 경로 · 위 표의 그 관점 한 줄 · 등급 정의 · 아래 표 형식만 넣는다. 각자 **표 줄만** 돌려준다:
   `| 등급 | 관점 | PRD 위치 | 지적 | 해결안 |` — PRD 위치는 절 번호·제목, 해결안은 PRD 에 바로 넣을 수 있는 1줄. 지적이 없으면 `지적 없음` 한 줄. 끝난 서브에이전트부터 받지 말고 다섯 개가 다 돌아올 때까지 기다린다.
3. **검토 파일을 쓴다** — PRD 와 같은 폴더의 `<PRD 이름>-review.md`. 머리 `# PRD 검토 — <PRD 이름>` · `> 요약: 심각 N · 주의 N · 제안 N` · 그 아래 `## 사업` `## 디자인/UX` `## 개발` `## QA` `## 보안` 순서로 절마다 표(머리줄 `| 등급 | 관점 | PRD 위치 | 지적 | 해결안 |`) 또는 `지적 없음`. 같은 위치·같은 지적은 한 줄로 합친다(관점은 먼저 잡은 쪽).
4. **검사기를 돌린다**:
   ```bash
   python3 "${FORGE_ROOT:-$HOME/forge}/shared/scripts/prd-review-lint.py" "<PRD 폴더>/<PRD 이름>-review.md"
   ```
   rc 1 이면 지적 줄을 모두 고치고 rc 0 이 될 때까지 다시 돌린다. `OK … 심각=N` 의 N 으로 5단계를 정한다.
5. **심각 처리** — 심각 0 → 6단계. 심각 ≥1 → 그 해결안대로 PRD 를 고치고 6단계로 간다 — 이 스킬을 다시 부르지 않는다. 고칠 수 없는 심각(사람 결정이 필요한 사업·권한 판단)은 그 줄을 보이고 **[STOP]**.
6. **PRD 머리 요약 3줄** — PRD 제목 줄 바로 아래에 넣는다(이미 있으면 바꾼다):
   ```
   > **PRD 검토(5관점 · YYYY-MM-DD)**: 심각 N · 주의 N · 제안 N — 상세 `<PRD 이름>-review.md`
   > 고친 것: <심각·주의 중 PRD 에 반영한 것 · 없으면 "없음">
   > 남은 것: <반영하지 않은 주의·제안 요약 · 없으면 "없음">
   ```
7. **보고** — 검토 파일 경로 · 검사기 `OK` 줄 · 고친 것/남은 것을 쉬운 말로. `/prd` 에서 불렸으면 다음 단계(7)로 돌아간다.

## 하지 않는 것
- 관점을 줄이거나 순서대로 하나씩 돌리지 않는다 — 다섯 개가 동시에, 1번.
- 프로젝트·조직 이름이나 절대 경로를 이 스킬에 박지 않는다 — 경로는 받은 PRD 에서 정한다.

## 실패 시 출력
- 검사기 rc 1 → 지적 줄(`<파일>:<줄>: <지적>`)을 그대로 보이고 고친 뒤 재실행. 3번 넘게 같은 지적이면 그 줄과 함께 "미완료"로 보고한다.
- 검사기 rc 2 → 사용법·파일 경로 오류 1줄을 보이고 멈춘다.
- 서브에이전트 하나가 실패하면 그 관점만 1번 다시 띄운다. 또 실패하면 그 절에 `지적 없음` 대신 실패 사실을 보고하고 "미완료"로 멈춘다.

## 자동 평가 (eval-rubric 통합)
검토 파일을 저장한 뒤 `/eval-rubric --target <review.md>` 로 4축 채점하고 `$HOME/.claude/skills/eval-rubric/scripts/eval-cases-append.py --skill prd-review` 로 `eval_cases.jsonl` 에 붙인다. 끄기: `EVAL_RUBRIC_AUTO=off`.
