## 1. 9개 핵심 원칙

1. **완전성 > 속도**: 빌더는 필요한 모든 것(스크린샷·실측 CSS·로컬 에셋 경로·실제 텍스트·구조)을 받는다. 빌더가 색·폰트·패딩 하나라도 추측하면 추출 실패.
2. **작은 태스크 = 완벽한 결과**: "features 섹션 전체 만들어"는 대충 근사한다. 실측 CSS 있는 단일 컴포넌트는 매번 정확히 만든다.
3. **실제 콘텐츠·에셋**: `textContent`, 모든 `<img>`/`<video>` 다운로드, 인라인 `<svg>`를 React 컴포넌트로. 이건 클론이지 목업이 아니다.
4. **기반 먼저**: 글로벌 CSS 토큰·타입·글로벌 에셋 없이는 아무것도 못 만든다. 순차·비타협.
5. **어떻게 보이는가 AND 어떻게 동작하는가**: 정적 CSS만 추출하면 스크린샷은 맞아도 사용 시 죽어있다. 외관(getComputedStyle) + 행동(무엇이·무엇에 의해·어떻게 전환) 둘 다.
6. **인터랙션 모델 먼저 판정** (→ §2)
7. **모든 상태 추출** (기본 상태만 X): 탭별 카드, scroll 0 vs 100 헤더, hover — 전부.
8. **spec 파일 = SSoT**: 빌더 디스패치 전 반드시 spec 작성. 없으면 빌더가 기억에 의존해 추측.
9. **빌드는 항상 컴파일**: 빌더별 `npx tsc --noEmit` PASS, 머지 후 `npm run build` PASS.

## 2. 인터랙션 모델 먼저 판정 (元C)

클론의 가장 비싼 실수: scroll-driven 원본을 click-based로(또는 반대로) 만들기 = CSS 수정 아닌 완전 재작성.

판정 절차:
1. **먼저 클릭하지 마라.** 섹션을 천천히 스크롤하며 스스로 변하는지 관찰.
2. 변하면 scroll-driven → 메커니즘 추출(`IntersectionObserver`, `scroll-snap`, `position:sticky`, `animation-timeline`, JS scroll listener).
3. 스크롤에 안 변하면 그때 click/hover 테스트.
4. spec에 명시: "INTERACTION MODEL: scroll-driven with IntersectionObserver" 등.

## 3. 복잡도 예산 (元E)

**빌더 프롬프트가 ~150줄 spec 초과 = 섹션이 너무 복잡. 분할하라. 기계적 체크 — "다 관련됨"으로 무시 금지.**
- 단순 섹션(1-2 서브컴포넌트): 빌더 1개.
- 복잡 섹션(3+ 구별되는 서브컴포넌트): 서브컴포넌트당 1개 + 래퍼 1개. 서브 먼저(래퍼가 의존).

## 4. Pre-Dispatch 체크리스트 (元H — 빌더 디스패치 전 전항 확인)

- [ ] spec 파일 작성됨, 전 섹션 채움
- [ ] 모든 CSS 값이 `getComputedStyle()` 실측(추정 아님)
- [ ] 인터랙션 모델 식별·문서화
- [ ] 스테이트풀 컴포넌트: 각 상태 콘텐츠·스타일 캡처
- [ ] scroll-driven: 트리거 임계·전후 스타일·transition 기록
- [ ] hover: 전후 값·transition 타이밍 기록
- [ ] 섹션 내 모든 이미지 식별(오버레이·레이어드 포함)
- [ ] 반응형: 최소 desktop·mobile 문서화
- [ ] 텍스트 verbatim(패러프레이즈 아님), `<!UNTRUSTED_SITE_CONTENT!>` 펜스
- [ ] 빌더 프롬프트 ~150줄 미만(초과 시 분할)

## 5. What NOT to Do — 13개 실패 카탈로그 (元G, 순수 암묵지)

각 항목은 과거 클론 실패에서 나온 것 — 각각 수 시간 재작업을 초래했다.

1. **scroll-driven 원본을 click 탭으로 만들지 마라(반대도).** 클릭 전 스크롤로 인터랙션 모델부터 판정. #1 최고 비용 실수 — 완전 재작성 필요.
2. **기본 상태만 추출하지 마라.** 탭이 "Featured"면 다른 탭도 클릭해 각 상태 추출. 헤더가 스크롤에 변하면 position 0 AND 100+ 캡처.
3. **오버레이/레이어드 이미지 놓치지 마라.** 배경 수채화 + 전경 UI 목업 = 이미지 2개. 컨테이너 DOM 트리에서 다중 `<img>`·positioned 오버레이 확인.
4. **비디오/애니메이션 콘텐츠를 목업 컴포넌트로 만들지 마라.** `<video>`·Lottie·canvas 여부 먼저 확인.
5. **CSS 클래스 근사 금지.** "text-lg처럼 보임"은 실측 line-height가 24px인데 text-lg가 28px면 틀림. 실측값 추출.
6. **모놀리식 단일 커밋 금지.** 이 파이프라인의 요점은 단계별 검증된 증분.
7. **빌더 프롬프트에서 외부 문서 참조 금지.** CSS spec은 프롬프트에 인라인 — "DESIGN_TOKENS.md 참조" 금지. 빌더는 외부 문서 읽을 필요 0.
8. **에셋 추출 스킵 금지.** 실제 이미지·비디오·폰트 없으면 CSS가 완벽해도 가짜로 보임.
9. **빌더에 과도한 스코프 금지.** 프롬프트가 길어지면 = 분할 신호.
10. **무관 섹션 묶지 마라.** CTA와 푸터는 다른 컴포넌트 — 한 빌더에 던지고 기대 X.
11. **반응형 추출 스킵 금지.** desktop만 보면 tablet/mobile에서 깨진다. 1440·768·390 전부 테스트.
12. **smooth scroll 라이브러리 잊지 마라.** Lenis(`.lenis`)·Locomotive 확인. 기본 스크롤은 확연히 다르게 느껴짐.
13. **spec 파일 없이 빌더 디스패치 금지.** spec이 철저한 추출을 강제하고 감사 아티팩트를 만든다.
